## 车道契约

- 原生导航的当前路线是唯一依据，`routeUID` 以十进制字符串传递，不丢失大整数精度。iOS 的 `AMapNaviInfo` 本身没有 HarmonyOS 的 `pathID` 字段；因此通过专属导航实例、会话代号、路线变更事件、重算屏障及变更后新的可靠地图匹配定位进行隔离，不伪造字段。
- `AMapNaviSegment` 仍然只是引导点集合。没有完整的未来物理路口数据源，不据转向指令猜测车道数。
- iOS 的 lane 字符串编码与鸿蒙 `LaneAction` 分别适配；背景方向与推荐分支取交集，未知及特殊车道保持标注。
- 仅当单信号灯 link 结束于引导点，或经过总长不超过 60 米的连续路口内部道路到达端点，且出口与下一段入口相连时采集。
- 保留实时面板 200 米关联范围；保存不受该距离限制。收到可关联车道立即入队落盘，不等待经过路口。
- 相同路段重复回调去重；推荐车道位置变更立即更新；结构或推荐转向冲突撤销。同一步骤冲突后不再次采集。
- 隐藏、弱定位、重算、退出和过期不删除已保存历史。新路段必须收到自己的车道回调。
- 历史使用 iOS 专属键和文件；未导入鸿蒙设备上的真实历史。严格匹配可能因 SDK 路网采样、道路名或几何变化而失效，不能承诺跨平台直接复用。

## 数据与生命周期

- 用户明确同意且授予精确位置后才配置、创建地图 SDK 对象；没有 Key 时不调用地图、搜索或导航。
- 只有真实 GPS 开始事件创建导航历史；模拟演示、搜索及选路取消均不记录。SDK 旧回调不更新新会话。到达状态不会被退出或延迟写入降级。
- 文件位于 Application Support/LaneAhead，采用原子写入。损坏文件保留并阻止自动覆盖，只有成功显式清除才解除保护；各类历史单独清除。
- 车道文件无时间、条数及 2 MB 读取淘汰。文件读写在独立 actor 中执行；写入失败保留待写变更，有界重试。数据量增大后仍需验证整份 JSON 序列化的内存和磁盘成本。
- 导航历史仅保存目的地、城市、地址、时间、状态和出发时规划里程；车道匹配键包含必要的进出口几何，保留在应用私有文件。没有历史上传端点；高德 SDK 的位置和网络处理另受其隐私政策约束。
- 诊断仅保存固定状态文本和计数，不写入 Key、道路、路线标识及坐标。每五秒节流，结束时强制入队保存；写入包含更新和撤销，不当作路口数。
- 原生 SDK 配置了导航所需的后台定位和语音模式；应用进入后台暂停自己的车道采集、传感器与装饰动画，返回等待新的可靠定位。持续导航能力仍须真机锁屏和实际行驶验证。

## 传感器适配

Core Motion 的 `userAcceleration` 单位为 g，转换为 m/s² 后进入 G 值引擎；它已经排除重力，不再次减 1g。Core Motion 的 gravity 指向重力方向，适配层取反以得到引擎使用的向上向量。坐标轴、安装方向、磁场精度映射需要在真机支架上核对。

请求 50 Hz，约 10 Hz 发布；500 ms 无更新时显示未知。G 值校准约两秒且不少于 40 个样本，检测移动、振动、平放及超过 15° 的姿态变化。屏幕朝向车尾、顶部朝上；无法仅靠重力判断装反或绕竖直轴旋转。

指南针使用已校准磁场、重力和最短角差滤波，平放／竖放参考带滞回。显示磁北，不能等同真北或 GPS 行驶方向。水平仪以屏幕平面为参考，不称作道路坡度。原始样本、校准及峰值不落盘，不上传。
